三层认知记忆系统架构总结：存储、检索与泛化方案

核心范式：右侧自然语言向量锚点解锁 → 左侧结构化槽位列 SELECT 唯一定位

事实记忆：动态演化 工作记忆：静态工单时间对齐 经验记忆：澄清归纳 + 快速闭环

二、统一向量锚点池与三层记忆分流检索

检索时不预先猜测查询哪一列，而是将单用户的全部短语锚点（10~30 条）放入统一向量锚点池，每个锚点自带 subtype 标签。输入话术匹配锚点后，按命中的标签分流取数：

1. 事实记忆：锚点解锁 → 二跳 SELECT

解决周期偏好、场景偏好与个人黑话复用

  1. 一跳解锁锚点：如话术命中 periodic_preference（“午间例行”），解锁左列 time_window='12:30-13:30', app='抖音', biz='openlive'；命中 expression（“千万别转圈”）解锁 rtt='50ms'。
  2. 二跳关联查询：以解锁出的 (app, biz, scene) 作为 WHERE 条件，去 preferred_value 或 scene_preference 表执行 SELECT。
  3. 唯一返回：仅返回得分最高的一条主记录，直接补齐 7 个槽位。
2. 工作记忆：时间窗换算 + 多列动态 SELECT

解决“上周/上个月初/昨天预约/之前那笔”跨期工单指代

  1. 时间列换算：基于当前 reference_time 将口语时间词换算为日期区间（昨天预约→Δ∈[1,3]天；上周→Δ∈[5,10]天；上个月初→上一自然月；上一次→ORDER BY created_at DESC LIMIT 1）。
  2. 可选列动态拼接：提及业务则加 service 过滤，提及应用则加 app 过滤，提及地点则由向量锚点转成标准 location 过滤（未提及的列不限制）。
  3. 两阶段收敛闭环：若 SELECT 出的规格唯一则单步回填；若仅说模糊词“之前”且查出 ≥2 种不同规格，则 Turn 1 留空画质/时延挂起追问，Turn 2 按用户补充的“最近那次”做二次排序锁定。
3. 经验记忆：一跳直达 & 双分支闭环

解决复杂场景业务映射与预热/顺延策略

  1. 分支 A（多轮澄清归纳）：首次遇到新场景未命中经验卡时，Turn 1 按字面理解，Turn 2 根据用户纠偏说明完成修改并在会话末结晶出 experience 卡片。
  2. 分支 B（单轮快速闭环）：后续会话首轮命中已激活 experience 卡片的触发词（如“连麦嘉宾”、“对一下直播词”、“重大活动保障”），无需二跳、无需追问，直接读取卡片左列的 action 规则（如改写为 抖音/开直播 或起保时间提前 30 分钟）一步闭环。

三、短窗口向量匹配（Sliding-Window Vector Matching）：提升开放口语泛化性

传统规则切分 / 整句向量的痛点
  • 无标点长句切不开：语音转写常一逗到底（如“今天我不去滑雪基地了改在酒店房间里趁着中午那个例行档期把抖音直播保障开上”），规则按标点切分失效。
  • 整句向量语义被稀释：30~40 字长句包含四五个实体，整句 Embedding 与 4 字锚点（“午间例行”）算余弦相似度会被拉低至阈值以下。
  • 否定词误伤全局：前半句“不去滑雪基地”若不精确定界，会误伤后半句的正常意图。
短窗口向量匹配 + 轻量解析方案
  • 6~10 字滑窗 + Max-Pooling：因为库内短语锚点长度均为 4~10 字，用长度 8~10 字、步长 4 字的滑窗切分长句（约 6~8 个短窗口，单 Batch 一次算完），每个锚点取所有窗口的最大余弦相似度。
  • 窗口级局部否定隔离：哪个滑窗命中了锚点，仅检查该滑窗内部及前 2~3 字是否含否定词（不/别/取消），只淘汰被否定的窗口锚点。
  • 时间解析“快路 + LLM 兜底”：常规词（昨天/上周/上个月）走 0ms 日期算术；非常规口语（如“九月中旬那会儿”）由模型转为 date_range 后再跑 SQL SELECT。
